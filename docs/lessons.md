# Engineering Lessons, Architectural Invariants & Historical Bug Post-Mortems

This document captures the hard-won architectural, security, wire-protocol, UI/UX, and multi-agent orchestration lessons from building `ai-quota-monitor`. Read this before modifying the plan, collector, crypto relay, or Android application.

---

## 1. Multi-Agent Orca Orchestration Lessons

### 1.1 Always Review the Architectural Plan *Before* and *Across* Implementation
- **What happened**: Initially, `grok` (`grok-4.7 --effort medium`) was dispatched to review `collector-service` and `android-app` in isolation against `docs/plan.md`. Both passed their isolated reviews (`APPROVED`), yet a subsequent dedicated **Plan & Cross-System Review** caught **Critical** integration bugs (`SYS-C1`: `nonce` vs `iv` JSON field mismatch in the AES-256-GCM Gist envelope; `SYS-C2`: GitHub's Sept 2025 API change returning `401` on unauthenticated secret-gist API reads; `SYS-H4`: `TailscaleApiClient.primeGrok()` decoding `SmartPrimeStatus` instead of `QuotaSnapshot`). Later, on Issue #3 (`APP-UX2`), running a supervised `grok-4.7` **Gate 1 Plan Review** against the feature spec *before* implementation caught 6 High and 3 Medium edge cases (`H1`–`H6`, `M1`–`M3`: `SharedPreferences` `contains()` vs `remove()` semantics, mutable `StringSet` aliasing, `settingsMutex` pin/hide races, all-hidden `heroBucket()` nullability, and `BurnVelocityChart` `100.0` default flat-line distortion) before a single line of code was written.
- **Rule Going Forward**:
  1. **Gate 1 (Plan Review)**: Run a supervised `grok` (`grok-4.7`, `medium` effort) review on the task spec + `docs/plan.md` + `docs/providers.md` *before* implementation begins on every feature or UX issue (`./scripts/review-plan-and-code.sh plan "<worktree>" --spec "<spec-file>" --issue <n>` or `orca orchestration worker-start --agent grok`).
  2. **Gate 2 (Worktree Review)**: Run `grok` on each implementation worktree after unit tests pass.
  3. **Gate 3 (Cross-System Integration Review)**: Run `grok` across `docs/` + `collector/` + `app/` together to verify producer/consumer contracts (JSON schemas, crypto envelopes, HTTP routes) match byte-for-byte.

### 1.2 Orca CLI & `grok` Invocation Quirks
- **Implementer routing & Antigravity alias**: Per `orca-cheap-workers`, dispatch implementers primarily with `--agent opencode2` (`opencode-go/deepseek-v4.1-flash`, passing neither `--model` nor `--effort`) and fall back to `--agent antigravity --model gemini-3.8-flash-high --effort high` (not `--agent agy`) only when OpenCode Go quota is `>= 80%` used or unavailable. Planner work uses `gemini-4-argon-medium` (`medium`); review work always uses `grok-4.7 --effort medium`.
- **Grok reviewer invocation**: In `orca orchestration worker-start`, `--agent grok` reads its model (`default = "grok-4.7"`) and reasoning effort (`default_reasoning_effort = "medium"`) from `~/.grok/config.toml` (rejecting `--model` / `--effort` flags) and checks `~/.grok/trusted_folders.toml` on startup. Always pre-register newly created child worktrees (`[folders."<worktreePath>"]\ntrusted = true`) in `~/.grok/trusted_folders.toml` before calling `orca orchestration worker-start --agent grok` so supervised Grok reviewer workers never block on interactive TUI folder trust (`agent-trust-workspace`). `scripts/review-plan-and-code.sh` now performs this `~/.grok/trusted_folders.toml` pre-registration automatically. For scripted CI/issue-comment posting (`scripts/review-plan-and-code.sh`), headless single-turn mode is also supported:
  ```bash
  grok -m grok-4.7 --effort medium --always-approve --cwd "<worktree-or-repo-path>" -p "<read-only review prompt>"
  ```
- **Valid `orca orchestration send --type` values**: When forwarding Gate 1 review findings or follow-up instructions to an active worker terminal via `orca orchestration send`, use `--type dispatch` (accepted enum: `status`, `dispatch`, `worker_done`, `merge_ready`, `escalation`, `handoff`, `decision_gate`, `question`, `heartbeat`; `--type steer` is rejected).
- **Worker settlement discipline**: Never run `orca orchestration check --ack <delivery_id>` for a `worker_done` message until you have (a) independently re-run the test/hygiene gates in the worker's worktree and (b) settled the worker terminal via `orca orchestration worker-release --dispatch <ctx_id>`.

## 2. Cross-Boundary & Cryptography Lessons

### 2.1 Never Test Producer & Consumer Crypto Only Against Self-Mocks
- **What happened (`SYS-C1`)**: Python's `collector/crypto_relay.py` emitted `{"v": 1, "alg": "AES-256-GCM", "nonce": "...", "ciphertext": "...", "tag": "...", "capturedAt": "..."}`. Kotlin's `GistEnvelopeDecryptor.kt` looked only for `"iv"`. Both unit test suites passed 100% because Python tested `decrypt(encrypt(x))` and Kotlin tested `decrypt(mockKotlinEnvelope)`.
- **Fix & Invariant**:
  - Lock a single canonical envelope schema in [`docs/providers.md`](providers.md) (`nonce` primary, `iv` accepted as alias).
  - Maintain a **Cross-Language Golden Test Vector** (fixed 32-byte key, fixed 12-byte nonce, fixed JSON snapshot, exact Base64 ciphertext & tag) asserted in both `collector/tests/test_collector.py` and `app/src/test/java/com/aiquotamonitor/domain/GistEnvelopeDecryptorTest.kt`.
  - Bind `capturedAt` across the outer envelope and inner decrypted snapshot so an attacker or stale cache cannot re-label an old ciphertext with a newer timestamp.

### 2.2 Base64 vs Hex Ambiguity on Short Binary Fields (`APP-M2/L3`)
- **What happened**: A 12-byte GCM IV encoded in Base64 is 16 characters long. If all 16 Base64 characters happen to fall in `[0-9a-fA-F]`, a naive `isHex` check decodes it as 8 hex bytes instead of 12 Base64 bytes, causing `GCMParameterSpec` to fail.
- **Fix & Invariant**: Only treat a string as hex when it has an explicit `0x`/`hex:` prefix or when its length equals `expectedByteLength * 2` (`24` chars for a 12-byte IV, `64` chars for a 32-byte key); otherwise decode as Base64 first and validate exact byte length (`12` bytes for IV, `16` bytes for GCM tag, `32` bytes for AES-256 key).

### 2.3 GitHub Secret Gist Relay Rules (Post-Sept 2025) (`SYS-C2`)
- **What happened**: Since September 2025, GitHub's REST API (`GET https://api.github.com/gists/{id}`) returns `401 Unauthorized` for unauthenticated reads of secret gists, and anonymous `api.github.com` requests are rate-limited to `60/hr` per IP. Furthermore, since November 2025, unlisted gists are scanned by GitHub secret scanning.
- **Fix & Invariant**:
  - Support **Direct Raw Gist URLs** (`https://gist.githubusercontent.com/<owner>/<gist_id>/raw/quota_snapshot.enc.json`), which require no GitHub token on the phone and bypass the `60/hr` REST API limit, **and** support an optional **GitHub Fine-Grained Read Token** (encrypted in Android Keystore) when fetching via `api.github.com/gists/{id}`.
  - Never put unencrypted tokens or machine hostnames (`socket.gethostname()`) inside the Gist; secrecy relies 100% on the 256-bit AES-GCM key stored only in `~/.config/ai-quota-monitor/config.json` (`0600`) and Android Keystore.

## 3. Upstream Provider Wire-Protocol Lessons

| Provider | Wire Pitfall | Required Defensive Rule |
| :--- | :--- | :--- |
| **`agy`** | `remaining_fraction` is fraction **LEFT** (`0.0..1.0`), whereas other providers report percent **USED**. Missing `remaining_fraction` if defaulted to `1.0` masks broken buckets (`COL-L10`). | Skip any bucket where `remaining_fraction` is `None`; clamp valid values to `[0.0, 1.0]`. |
| **`opencode go`** | Upstream `GET https://opencode.ai/zen/go/v1/usage` nests windows under `{"usage": {"rolling": ...}}`, which becomes `usage.usage.*` when wrapped (`SYS-H5`). Requires `User-Agent: opencode/2.2.2`. | Accept both `usage.*` and `usage.usage.*`. Fail closed (skip bucket / mark `parse_error`) if `percent` is missing or non-numeric—never default to `0% used`. |
| **`grok`** | Wraps `onDemandCap`, `onDemandUsed`, and `prepaidBalance` in `{"val": <number>}` objects. Can report usage in `creditUsagePercent` or `productUsage[].usagePercent` (`SYS-H5`). | Unwrap `{"val": ...}` recursively. Fail closed (`status = "parse_error"`) if neither usage field is numeric. When both exist, use `max(creditUsagePercent, productUsage)` so a `0` in one field never hides real usage in the other. Fall back to secondary billing URL on `HTTPError`, `URLError`, timeout, or `parse_error`. |
| **All Providers** | Upstream `resetsAt` can be `null` when a window has not started (`SYS-H5`). | `QuotaBucket.resetsAt` must be nullable (`String? = null`) in both Python and Kotlin (`kotlinx.serialization`). |

## 4. Android Security, Compose & Glance Widget Lessons

1. **Fail-Closed Android Keystore (`APP-H1`, `SYS-H6`)**:
   - Never fall back to returning plaintext if `AndroidKeyStore` encryption fails on a real device. Use an ephemeral in-memory AES key fallback *only* when `KeyStore.getInstance("AndroidKeyStore")` is unavailable in host JVM unit tests.
   - Always set `android:allowBackup="false"` and configure `@xml/data_extraction_rules` and `@xml/backup_rules` so encrypted preferences and cached snapshots are excluded from cloud/ADB backups.
2. **Private-Network Cleartext HTTP Guard (`APP-H2`, `SYS-H3`)**:
   - Android `targetSdk = 36` blocks cleartext HTTP by default, while the local Mac collector over Tailscale uses `http://100.x.y.z:8741`.
   - Enforce in `TailscaleApiClient` that `http://` URLs are permitted **only** for Tailscale CGNAT (`100.64.0.0/10`), loopback (`127.0.0.1`, `localhost`), RFC1918 private LAN, and `*.ts.net` hosts—never send the bearer token over `http://` to a public internet host.
3. **Glance Widget State Synchronization (`APP-M4`, `SYS-H6`)**:
   - `GlanceAppWidget` does not automatically re-render when `SharedPreferences` changes. Explicitly call `QuotaCompactWidget().updateAll(context)` and `QuotaWideWidget().updateAll(context)` whenever a new snapshot is saved or the `% Left` / `% Used` polarity toggle changes.
   - Always badge fallback demo data (`SeedData`) with `"DEMO"` on widgets and flag snapshots older than 2 hours (`7200s`) as `STALE`.
4. **Google Stitch MCP Lessons**:
   - `create_design_system` only accepts specific font and color variant enums (`MANROPE`/`INTER` + `FIDELITY`; `PLUS_JAKARTA_SANS` + `EXPRESSIVE`; `SPACE_GROTESK`/`GEIST` + `VIBRANT`).
   - Direct HTTP `GET` against Stitch CDN URLs (`lh3.googleusercontent.com/aida/...`) returns `401 Unauthorized`; always use Stitch MCP's `download_file` tool RPC to fetch base64-encoded PNG and HTML assets.
5. **Compose Form Draft State vs Composite Settings Updates (`APP-UX1`)**:
   - Never key form draft `remember(...)` state on an entire composite `SyncSettings` object (`remember(settings)`) when another control on the same screen (such as `ActiveHoursSlider`) writes partial updates to `SyncSettings`—doing so resets unsaved text fields while the user is typing.
   - Always key draft state only on the specific credential strings (`remember(settings.tailscaleUrl, settings.tailscaleToken, settings.gistId, settings.gistAesKey, settings.githubToken)`), and serialize all repository settings writes (`saveSettings`, `updateActiveHours`, `updateSettings`, and `testConnection` commits) under a single `Mutex` (`settingsMutex`) that merges onto the latest persisted settings.
6. **Non-Destructive Connection Probing & Honest Cache vs Demo Labeling (`APP-UX1`)**:
   - A "Test Connection" action (`testConnection(draftSettings)`) must probe using the draft credentials without overwriting stored Keystore secrets if the probe fails, must restore the prior `ConnectionState` on failure, and must combine both Tailscale and Gist error causes when both fail.
   - Never persist `SeedData` into `cached_snapshot` preferences—only persist real snapshots from `TAILSCALE_LIVE` or `CLOUD_RELAY_SYNCED` so `ConnectionState.OFFLINE` ("Offline Cache") is never shown for demo seed numbers.
   - Use a single shared predicate (`SyncSettings.hasUsableTransport`: `tailscaleUrl.isNotBlank() || (gistId.isNotBlank() && gistAesKey.isNotBlank())`) across the Dashboard onboarding card, `SyncHubSheet`, and `WidgetsAndSyncScreen` so a Gist ID without an AES key is marked `"Incomplete (needs ID & AES key)"` rather than `"Configured"`.
7. **First-Run Discoverability, Port Consistency, Wireless ADB Bonjour Discovery & Release APK Workflow**:
   - Never bury first-run endpoint configuration at the bottom of a secondary tab or make status sheets read-only. Surface a first-run onboarding card (`ConnectCollectorCard`) on the Dashboard and make `SyncHubSheet` directly editable.
   - Keep default ports (`8741`) identical across `collector/config.py`, `collector/cli.py`, UI placeholders, unit tests, and `README.md`.
   - Document Android 14–16 Wireless Debugging's two-port flow explicitly (`adb pair <ip>:<pairing-port> <code>` uses the temporary popup port, whereas `adb connect <ip>:<connect-port>` uses the main Wireless Debugging screen port).
   - When a previously paired Pixel 8 Pro reconnects to Wi-Fi with a rotated dynamic port and `adb devices` / `adb mdns services` return empty, macOS Bonjour (`dns-sd -B _adb-tls-connect._tcp local.` → `dns-sd -L <instance> _adb-tls-connect._tcp local.` → `dns-sd -G v4 <host>`) reliably discovers the active dynamic port. Even if macOS Local Network privacy or Wi-Fi AP client isolation blocks direct unicast TCP to the LAN IP (`No route to host`), connecting to the phone's Tailscale CGNAT IP (`100.x.y.z:<port>` from `tailscale status`) at that mDNS-discovered port routes over the `utun` tunnel and succeeds immediately (automated in `scripts/deploy-pixel8pro.sh`). **Never** log or commit the `_adb-tls-connect._tcp` instance name, because Android embeds the hardware device serial number inside it.
   - In `.github/workflows/release.yml`, always build both `assembleDebug` and `assembleRelease` (alongside `lintDebug testDebugUnitTest`) whenever the GitHub Release step uploads both `app-release.apk` and `app-debug.apk`.
8. **Multi-Stage Public-Repo Git Safety Guards & GitHub Issue-First Workflow (`SEC-G1`)**:
   - In shell `pre-commit` hooks, matching `$f` against `config.json` or `.env` in a `case "$f" in` statement only matches root-level files and silently lets `sub/config.json` or `app/.env.local` slip through, while `for f in $staged` splits paths containing spaces (`Demo Build.APK`). Always iterate with `while IFS= read -r f`, extract `base=$(basename "$f")`, lowercase it (`tr '[:upper:]' '[:lower:]'`), and fail closed if `git cat-file -s ":$f"` fails.
   - Use `grep -v '^+++' | grep '^+'` rather than `grep -E '^\+[^+]'` when extracting staged/commit diff additions so added lines starting with a literal `+` are never skipped.
   - In `commit-msg`, never strip `^#` lines before scanning for secrets/paths/emails—Markdown headings (`## [PLAN]`) passed through `scripts/gh-issue-workflow.sh` or written in commit bodies start with `#` and must be scanned too. Only strip `^#` git status comments when checking for the `#<issue-number>` reference.
   - In `pre-push`, always read `<local_ref> <local_oid> <remote_ref> <remote_oid>` from `stdin` and inspect the actual pushed commit range (`git ls-tree -r -l "$local_oid"` and `git log "$range" -p`) so secrets committed with `git commit --no-verify` or removed in a later working-tree edit are still blocked from reaching GitHub.
   - Enforce the **GitHub Issue-First Workflow** via `scripts/gh-issue-workflow.sh` (`create`, `comment <id> <plan|implementation|testing|review>`, `verify`, `close`) and `.githooks/commit-msg` (`#<issue-number>` check when `origin` is configured).
   - **Emulator screenshots belong on the issue (`SEC-G2`)**: A testing comment cannot prove a shot was taken before the edit. The plan comment now chooses `UI evidence: before-and-after` or `UI evidence: none`. For the first, `before-shot` must be run while UI files are still clean, and `.githooks/commit-msg` rejects the UI commit until that receipt is present. The testing comment then has to upload that same Before image plus an After image. `git commit --no-verify` skips the hook. A merge commit is exempt, because it does not create a new UI edit. The hook does not drive the emulator.
9. **Android Adaptive Launcher Icons & Material You Theming Invariants (`APP-ICO1` / Issue #2)**:
   - Android adaptive icons require a 108dp x 108dp canvas where all critical visual elements MUST remain within the 66dp diameter safe area circle ($R \le 33\text{dp}$, center `(54, 54)`). The outer 18dp is subject to variable OEM masking (Circle on Pixel, Squircle on Samsung One UI, Rounded Square on HyperOS) and physics-driven parallax shifts during touch and launch animations.
   - For Android 13+ (API 33+) Material You dynamic theming, `<monochrome>` cannot simply be a copy of foreground vectors with stripped fills. It must be an alpha mask (white `#FFFFFF` paths with varying `android:strokeAlpha` / `android:fillAlpha`). Crucially, because VectorDrawable uses source-over blending without compositing clear modes, stacking a subsequent path with `#00000000` does **not** punch a hole in previously painted geometry. True cutouts (such as center core pips) **must** be combined with the outer glyph into a single `<path>` using `android:fillType="evenOdd"`.
   - Decouple `<background>`, `<foreground>`, and `<monochrome>` into separate vector drawables and reference them from both `ic_launcher.xml` and `ic_launcher_round.xml`.
   - The launcher icon implements a simplified Chronos telemetry glyph (270° sweep, pace pip, delta arrow with core well knockout) tailored for static launcher scannability, adapting the visual motif of the in-app Hero Bottleneck card rather than replicating interactive gauge elements. Verification requires both unit assertions and live home screen / app drawer inspection.
10. **Persisted Model Visibility, Hero Pinning & Chart Telemetry Invariants (`APP-UX2`)**:
   - **`SharedPreferences` StringSet Semantics**: An absent preference key (`!prefs.contains(KEY_HIDDEN_BUCKETS)`) must be distinguished from a user-selected empty set ("Show All" — `prefs.contains(KEY_HIDDEN_BUCKETS) == true`). Never `remove()` the preference key to represent "Show All" or the default hide (`3p-5h`, `3p-weekly`) will be reinstated on app restart. Furthermore, Android's `getStringSet` can return mutable internal references—always store and return defensive copies (`HashSet(it)`) on get and put.
   - **Mutex-Serialized Visibility & Pinning**: Pinning a bucket must automatically unhide it in the same `settingsMutex` transaction; hiding a currently pinned bucket must clear `pinnedBucketId` in the same transaction so hidden buckets never hijack the Hero spotlight. In UI callers (`ModelFilterSheet`), invoke only `onSetPinnedBucket`—never issue a redundant `toggleBucketVisibility` before pinning, which introduces a race condition between concurrent coroutines where an unhidden pin is immediately re-hidden.
   - **Filter Completeness Across All Dashboard Surfaces**: Hidden quotas must leave all dashboard surfaces, including `ProviderBentoRow`. If all buckets for OpenCode or Grok are hidden, omit the respective card; when partially hidden, drive radial gauges from visible buckets and select the active visible bucket on click.
   - **Glance Preview-Widget Fidelity**: In-app widget previews (`GlancePreviewCard`) must faithfully reflect the same configuration options (such as `QuotaPolarity`) across both the 2x2 tile (`displayPercent`, `Left`/`Used`, `REM`/`USED`) and the 4x2 Orca Stage Deck (`role.displayPercent(polarity)`, dynamic color coding, and `REM`/`USED` header tag) as the actual home-screen AppWidgets (`QuotaCompactWidget` and `QuotaWideWidget`).
   - **Sub-Metric Component Interaction Scoping**: When nesting sub-metric components (such as the OpenCode 5h Rolling pill) inside a clickable parent card, assign an explicit click modifier to the child pill targeting its own bucket ID so tapping the secondary metric opens its specific detail sheet rather than inheriting the primary gauge's bucket.
   - **Domain `heroBucket` Fallback & Tie-Breaking**: When all visible buckets are hidden and no usable pin exists, `heroBucket()` must return `null` (causing `HeroBottleneckCard` to be omitted) rather than falling back to the global `bottleneckBucket` which would display a hidden bucket. Equal `remainingPercent` values must tie-break deterministically by `id` ascending (`compareBy<QuotaBucket> { it.remainingPercent }.thenBy { it.id }`).
   - **Dynamic Velocity Bezier Charting without Flat Lines**: In `BurnVelocityChart`, never substitute `100.0` for missing history keys—doing so draws misleading flat lines across 24h for unrecorded streams. Only plot streams that have at least one recorded history point, draw curves strictly across valid points, and distinguish "All models hidden" from "No history recorded yet" in the empty state.
   - **Progressive Disclosure & BackHandler Priority**: Secondary pools (`AntigravityBucketsCard`) must default to a clean collapsed summary header to declutter the dashboard. When stacking modal sheets (`BucketDetailSheet`, `SyncHubSheet`, `ModelFilterSheet`), prioritize the topmost layer's `BackHandler` so pressing Back dismisses sheets in reverse z-order without interfering with bottom tab navigation.
   - **Automated Linting Rules (`app/lint.xml` + `AQM-LINT-001..008`)**: Promote Android Lint's `MutatingSharedPrefs`, `CommitPrefEdits`, `SetJavaScriptEnabled`, `JavascriptInterface`, `HardcodedDebugMode`, `MutableCollectionMutableState`, and `RememberSaveableSaverParameter` to `severity="error"` in `app/lint.xml` (`abortOnError = true`), and enforce `AQM-LINT-001` through `AQM-LINT-008` in `collector/tests/test_repo_hygiene.py` (`test_architectural_and_code_lint_rules`) so regressions in WebView usage, `SharedPreferences` `StringSet` aliasing, `remember(settings)` draft clobbering, `SeedData` cache pollution, `BurnVelocityChart` `100.0` defaults, or `ModelFilterSheet` pin/toggle races fail CI immediately.
11. **Personal Device Isolation, Local ARM64 AVD Testing & Adaptive Icon Plate Polish (`APP-ICO2` / Issue #5)**:
   - **Personal Device Isolation & Off-Limits Invariant**: Personal hardware connected over USB or wireless ADB must NEVER be automatically targeted or probed by automated agents or deployment scripts. Always instantiate and attach a dedicated local virtual device (`Pixel_8_Pro_Virtual`) or require explicit `--device <serial>` confirmation before touching any physical hardware.
   - **Local ARM64 AVD Management**: Apple Silicon Macs run native ARM64 Android Virtual Devices with macOS Hypervisor acceleration (`qemu`). Created via `android sdk install "system-images/android-35/google_apis/arm64-v8a"`, `avdmanager create avd -n Pixel_8_Pro_Virtual -d pixel_8_pro`, and booted/attached via `orca emulator attach Pixel_8_Pro_Virtual`. Once attached, Orca streams the virtual device in its Emulator pane, enabling full UI Automator hierarchy dumps (`orca emulator ax --device emulator-5554`) and screencaps (`adb -s emulator-5554 exec-out screencap -p`).
   - **Adaptive Icon Full-Bleed Background Invariant**: Never place sub-canvas geometry (such as an inner circle of radius 36dp) inside `ic_launcher_background.xml`. When the launcher's circular mask diameter exceeds 72dp (e.g., Pixel Launcher's ~76–80dp circular mask), an unintended outer rim of the base layer appears. On non-circular OEM masks (e.g., Samsung One UI squircle), a circle inside a squircle is visibly jarring. The background layer must be a uniform full-bleed color (or continuous gradient) across the full 108dp canvas.
   - **Inactive Gauge Track Contrast on Dark Backgrounds**: An inactive track rendered in `#172226` against an obsidian background (`#0B0F12` / `#11181C`) has insufficient luminance delta at standard launcher scale, making the gauge look like an incomplete floating "C" arc rather than a complete dial with a progress fill. The inactive track must maintain higher contrast (e.g., `#243338` or ~15–20% alpha) to be legible at all brightness and scale levels.
   - **Emulator-Aware Deployment Script (`scripts/deploy-pixel8pro.sh`)**: The deployment script must support explicit target specification (`--device <serial>`, `--emulator [avd-name]`) and refuse to blindly deploy to an adb-attached device when multiple devices are attached.
   - **Automated Linting Rules (`AQM-LINT-009` & `AQM-LINT-010`)**: Promote Android Lint's `IconXmlAndPng`, `IconLocation`, and `MipmapIcons` to `severity="error"` in `app/lint.xml`, and enforce `AQM-LINT-009` (icon lint rules) and `AQM-LINT-010` (deploy script device/emulator targeting safety) in `collector/tests/test_repo_hygiene.py`.
    - **Themed-Icon Verification on `emulator-5554`**: Pixel Launcher applies the `<monochrome>` layer on the home screen, but the app drawer can retain a stale full-color icon cache after toggling **Wallpaper & style → Themed icons**. For deterministic themed evidence, enable the toggle (Launcher prefs `themed_icons=true` / `Settings.Secure` `themed_icons`), restart the launcher, drag the app icon onto the home screen, and capture there; do not treat an unthemed drawer as a monochrome-layer regression.
12. **Lifecycle-Aware Foreground Auto-Sync, Single-Flight Mutex & Non-Blocking Age Feedback (`APP-SYNC1` / Issue #1)**:
    - **Background ticks must never borrow `ConnectionState.SYNCING`**: `ConnectionSettingsForm` disables Test/Save while `SYNCING` and `testConnection` restores the prior state only when it is not `SYNCING`; a background poll that sets `SYNCING` therefore disables settings controls and can corrupt probe-state restoration. Drive background work through a separate `isAutoSyncingFlow` / `isAutoSyncing` flag and preserve the prior `ConnectionState`.
    - **One `syncMutex` + monotonic generation for every network/snapshot writer**: `refresh`, `testConnection`, `primeGrok`, `updateActiveHours`, and the refresh inside `saveSettings` must serialize through a mutex separate from `settingsMutex`; auto-sync ticks must skip immediately with an atomic `tryLock()` (never a check-then-act `isLocked`) rather than queueing, and a skipped tick must not stamp `lastSyncAttempt`. Keep `settingsMutex` acquisitions strictly outside `syncMutex` (never nested, including `testConnection`'s draft-probe persistence) to avoid lock-order inversion and Save/Test deadlocks.
    - **Resume debounce measures attempts, not successes**: stamp `lastSyncAttemptEpochMsFlow` at the start of every actual refresh (including failures, `saveSettings`, and the live network paths of `primeGrok` / `updateActiveHours`) and gate resume on a 30s `AUTO_SYNC_MIN_GAP_MS`; poll every 60s (`AUTO_SYNC_INTERVAL_MS`) while `Lifecycle.State.STARTED`. Never add a second `ON_START` / `LifecycleResumeEffect` observer alongside `repeatOnLifecycle`.
    - **Foreground auto-sync eligibility**: require `settings.hasUsableTransport`, `scrubOffsetHours == 0.0`, `!isPriming`, `connectionState != SYNCING`, and `!isAutoSyncing`. Background refresh must never write or clear `_userMessage`.
    - **Freeze the scrub base snapshot**: `HorizonSimulator.project` recomputes from the repository base, so a refresh landing mid-drag would move gauges under the user's finger. Capture `scrubFrozenSnapshot` when the offset transitions from `0.0` to `> 0.0`, project it while scrubbing, and clear it on reset so the latest snapshot appears immediately at `0.0`.
    - **Age feedback must be local and non-blocking**: parse `capturedAt` defensively (`""` for blank/unparseable, `"Just now"` for `< 60s` or negative) and drive a 30s lifecycle-aware clock (`produceState` + `repeatOnLifecycle(STARTED)`) rather than waiting for a network poll; append ` · <age>` to the dashboard status pill and sync-hub status card. Drive `isStale` from `activeSnapshot` (so it respects the frozen scrub base) and OR it with `ageSeconds(nowEpochMs) > 7200` in the UI so the `(Stale)` badge crosses the boundary on the same tick.
13. **Configurable Widget Buckets, Two-Pass Fallback & Glance Session Reactivity (`APP-UX4` / Issue #4)**:
    - **Ordered lists need a string, not a `StringSet`**: `SharedPreferences.putStringSet` does not preserve slot order, so `wide_widget_bucket_ids` is a comma-delimited `putString` that is trimmed, blank-filtered, `distinct()`, capped at `MAX_WIDE_WIDGET_SLOTS = 3`, and returned as a fresh immutable `List`. Missing, blank, and empty all mean the "Orca Roles (default)" mode and the key is removed; never copy the `KEY_HIDDEN_BUCKETS` `prefs.contains(...)` contract onto it.
    - **Reserve before filling (two-pass resolution)**: In custom wide mode, resolve every explicitly requested `role:` token or concrete bucket id first and record its `primaryBucketId` / bucket id in `usedBucketIds`, then fill null slots from the sorted visible pool excluding reserved ids. Otherwise an earlier missing slot steals a later slot's configured bucket. Default mode reserves all visible `orcaRoles.take(3)` primaries before filling holes. Both modes always return exactly 3 cells; an exhausted pool emits `Double.NaN` placeholders (`"--"`, slate `#94A3B8`) instead of shrinking the deck.
    - **Never copy role numbers from the primary bucket**: `OrcaRoleReadiness.remainingPercent` is the aggregate (for `BUILDER`, `min(gemini-5h, opencode-rolling)`). Role cells set `remainingPercent` from the role and `usedPercent = (100.0 - remainingPercent).coerceAtLeast(0.0)`; pace may still come from `findBucket(primaryBucketId)`. A fallback substitute must carry the substitute bucket's own id, category, title, and percents, never the missing selection's labels.
    - **Glance sessions do not re-enter `provideGlance`**: an active session (~45s) ignores `updateAll()` for captured values. `QuotaCompactWidget` / `QuotaWideWidget` must read polarity, hidden ids, pin, widget selection, and `getCachedSnapshotJson()` inside `provideContent`, then resolve, so a chip tap during the session repaints immediately. Keep `updateAll` strictly after `settingsMutex` is released.
    - **In-mutex list mutation**: `toggleWideWidgetBucket` must read the stored list, append/remove/dedupe/cap, and persist inside `settingsMutex`; computing the next list from a `StateFlow` in the `ViewModel` loses rapid taps. Concrete ids may be auto-unhidden in the same transaction (matching the pin invariant), but `role:` tokens never touch `hiddenBucketIds` and `toggleBucketVisibility` is never called from the widget-selection path.
    - **NaN fails every comparison**: `displayPercent.isNaN()` must be checked before `< 20` / `< 40` thresholds, otherwise an "All models hidden" cell falls through to the green healthy branch. Guard both previews and both widgets, render `--` in slate, and suppress the pace pill. Never reintroduce the `?: 35.0` preview stand-in.
